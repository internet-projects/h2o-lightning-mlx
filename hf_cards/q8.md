# H2O-Lightning-4B — MLX 8-bit

An 8-bit MLX conversion (affine, group size 64; mlx-vlm 0.7.8) of [h2oai/h2o-lightning-4b](https://huggingface.co/h2oai/h2o-lightning-4b) **v1.4.1** (commit `cc18ee330e6895c41b9a60f37a0dd122dc4c3461`), for Apple Silicon. 4.8 GB. Supports H2O's **two-way reading** and **Box questions**.

Published by [NetProjects](https://netprojects.com) (Internet Projects Ltd). Not affiliated with H2O.ai.

This is a **decision model**, not a chat model. It returns a probability for each answer option (or, for a Box question, a bounding box), not free text.

> **Serve it with the H2O shim, not with `mlx_lm.server` or a plain `mlx_vlm` generate call.** The generic "Use this model" snippets Hugging Face shows for MLX models do not return the label probabilities this model is made for. The commands below set it up with H2O's official shim, unmodified, on top of [h2o-lightning-mlx](https://github.com/internet-projects/h2o-lightning-mlx), which reads the label log-probabilities with a float32 head, as the original does on vLLM.

Within one item of H2O's own result in both modes, and the same answers as the original weights on MLX: the recommended MLX build.

**Two-way reading.** H2O v1.3+ answers under two attention patterns, and two-way is its recommended default. This build serves both from one engine: a request picks `"attention_mode": "two-way"` or `"one-way"`, and two-way is the default. Before its first two-way answer, H2O's shim checks the engine against the answers H2O recorded on the release weights; this build matches them to within 0.014 (tolerance 0.05).

**Box questions** (always on since v1.4.0): ask for a bounding box of a named object in an image and get `box`, a calibrated `confidence`, `present` and `found`. The facade answers H2O's guided box generation exactly as the shim requests it. On H2O's receipt example, the box for the total-amount line has confidence 0.97.

**Speed** (MacBook Pro M5 Max, 27 October 2026, through `serve.sh`, one request at a time): about 63 ms per JevBench item; a 2,000-token record in 0.46 s two-way and 0.39 s one-way; a 32K-token state in 14.3 s two-way and 7.8 s one-way. **Two-way memory grows quickly with long inputs** (MLX peak 55 GB at 32K tokens, against 8.9 GB one-way): for long inputs on a Mac with less than 64 GB, use one-way.

**Images.** Image input works through the unchanged shim. On H2O's own receipt example this build gives the same answers as the original weights. It is not a reproduction of H2O's image benchmark.

**About v1.4.1** (from H2O's card): the v1.4.0 fine-tune continued on more training data, with unchanged calibration constants; stronger on retrieval and on six task families the added data covers (including choosing a function to call), level on H2O's held-out decision skills overall. The shim now checks at start that the engine uses the training tokenizer (`tokenizer/`, Qwen2Tokenizer), which this build ships and the facade uses.

**Limits** (as for the original): mostly evaluated in English; works best with about 16 answer options or fewer; no explanations and no video input.

```bash
git clone https://github.com/internet-projects/h2o-lightning-mlx && cd h2o-lightning-mlx && ./setup.sh
hf download netprojects/h2o-lightning-4b-mlx-q8 --local-dir mlx-q8
MODEL=mlx-q8 ./serve.sh # http://127.0.0.1:8741/v1/systemone
```

**Versions.** `main` is H2O v1.4.1 (27 October 2026: rebuilt from v1.4.1, new upstream weights). Earlier builds stay available: H2O v1.4.0 (two-way, 206 / 231) with `--revision v1.4.0`, H2O v1.3.1 (two-way, 203 / 231) with `--revision v1.3.1`, and H2O v1.2.3 (one-way, 205 / 231) with `--revision v1.2.3`; use each with the matching tag in the GitHub repo (`git checkout v1.4.0`).

**Full precision:** use the original weights, [h2oai/h2o-lightning-4b](https://huggingface.co/h2oai/h2o-lightning-4b), with the same repo and shim. There is no separate bf16 copy here.
